# Можно ли использовать дополнительные датасеты

> Разбор по тексту ТЗ кейса **«Agentic AI для прогнозирования выработки ВЭС»** (HackAlem AI).

---

## Коротко

- ✅ **Погодные данные из открытых источников можно и нужно брать**, это прямое требование ТЗ.
- 🔴 **Для тестового периода запрещены** фактические погодные значения и любые данные, ставшие известными после момента прогноза.
- 🟡 **Остальное в ТЗ не упомянуто**, это серая зона, её лучше уточнить у организаторов.

---

## 1. Что ТЗ прямо разрешает

Цитаты из ТЗ:

> «Самостоятельно получает по координатам ВЭС **из открытых источников погодные прогнозы**…»

> «**Выбор открытых источников погодных данных**, ML-моделей, методов обработки данных и архитектуры AI-агента остаётся за участниками.»

**Вывод:** внешние погодные данные обязательны, а источник выбирает команда. Подходят, например:

- Open-Meteo (Previous Runs API, Historical Forecast API)
- NOAA GFS
- ECMWF (IFS / Open Data)
- DWD ICON

---

## 2. Единственное явное ограничение

> «…использовать **архивные прогнозы погоды, которые были доступны на соответствующий момент времени**, а не фактические погодные значения, ставшие известными позднее.»

Для прогноза за тестовый период (февраль 2026) это правило жёсткое:

- ❌ реанализ (ERA5 и аналоги) как вход для прогноза;
- ❌ фактические данные метеостанций за прогнозируемые часы;
- ❌ любые прогнозы, выпущенные **после** момента T.

Иначе это **утечка данных** (data leakage).

---

## 3. Сводная таблица

| Что | Оценка | Комментарий |
|---|:---:|---|
| Архивные прогнозы погоды, доступные на момент T | 🟢 можно | Прямое требование ТЗ |
| Несколько погодных моделей (ECMWF, GFS, ICON) | 🟢 можно | «Выбор источников за участниками» |
| Реанализ (ERA5) **для обучения** на 2023–2025 | 🟡 скорее можно | Прямого запрета нет. Но честнее учить на тех же архивных прогнозах, что будут в тесте, иначе модель привыкнет к «идеальной» погоде |
| Фактическая погода с метеостанций **до** момента T | 🟡 скорее можно | Эти данные уже известны на момент T, так что правило не нарушается |
| Данные других ВЭС, открытые наборы кривых мощности | 🟡 не упомянуто | Не погода, в ТЗ про такое ничего нет |
| Предобученные модели (погодные модели-фундаменты и т.п.) | 🟡 скорее можно | «Выбор ML-моделей остаётся за участниками» |
| Данные турбин за февраль 2026 из любых источников | 🔴 нельзя | Это тестовая выборка |
| Любая погода за тестовый период, ставшая известной после момента T | 🔴 нельзя | Прямой запрет ТЗ |

**Легенда:** 🟢 разрешено · 🟡 серая зона · 🔴 запрещено

---

## 4. Что делать

### 4.1. Уточнить у организаторов

- [ ] Можно ли использовать **реанализ (ERA5)** для обучения модели?
- [ ] Можно ли использовать **фактические данные метеостанций** за период до момента прогноза?
- [ ] Можно ли использовать **внешние данные, не связанные с погодой** (другие ВЭС, справочные кривые мощности)?
- [ ] Есть ли **ограничения на предобученные модели** и внешние LLM API?

### 4.2. Раскрыть всё в README

Воспроизводимость и прозрачность дают **25 баллов**. Добавьте в README отдельный раздел:

```markdown
## Источники данных

| Источник | Что берём | Обучение | Прогноз (тест) |
|---|---|:---:|:---:|
| Датасет организаторов | ветер, мощность, температура турбин | ✅ | история до T |
| Open-Meteo Previous Runs API | архивные прогнозы на момент T | ✅ | ✅ |
| ...  | ... | ... | ... |

Гарантия отсутствия утечки: на этапе тестового прогноза используются
только данные, опубликованные до момента T (issue time ≤ T).
```

### 4.3. Основной вариант, безопасный при любом ответе

- **Обучение:** архивные прогнозы Open-Meteo (Previous Runs API, данные есть примерно **с середины 2024 года**) в паре с фактической мощностью турбин.
- **Прогноз:** те же архивные прогнозы на момент T.
- **Плюс:** обучение и тест устроены одинаково, поэтому ни один пункт ТЗ не нарушается.

> 💡 Если организаторы разрешат ERA5 или Historical Forecast API для 2023 – начала 2024, их можно добавить как **дополнительные** данные для обучения. Основной вариант от этого не ломается.
